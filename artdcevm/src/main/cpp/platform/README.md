# 平台代码分层

当前仅支持 ARM64。跨版本实现只有一份，版本差异只体现在固定源码声明上。

| 目录 | 内容 |
| --- | --- |
| `common/` | 跨版本实现：结构重定义引擎、校验策略、公开 JVMTI 结构读取、方法退役与运行时探测 |
| `abi/arm64/common/` | Android 11–17 源码中一致的 ART 固定声明（附源码出处与 `static_assert`） |
| `abi/arm64/androidNN/` | 只放 Android NN 源码中与其他版本不同的声明；每个版本一个目录，不放其他版本的内容 |
| `symbols/` | 命名 ELF 符号目录；`tools/check-structural-symbols.py` 对照设备库核对 |

新增代码先确认是否确有版本差异：没有就放 `common/`，有就只把差异声明放进对应版本目录，不复制整套实现。目前的版本差异是 `mirror::Class` 的字段数组（11–15 为 `ifields_`/`sfields_`，16–17 为 `fields_`）以及 Android 11 的 `ArtMethod`。

能力由运行库的实际符号与运行时探测决定，不按机型、SDK 或构建编号放行。方法退役的 Hook 只在所有精确名称都能解析时安装；每次事务在 ART 仍可失败的阶段，用 ART 自身的查找服务和 JVMTI 视图核对各版本声明，选中一致的那一个后才接管成员映射。SDK 只用于排除早于平台版本的候选并决定尝试顺序，因为 ART 模块不会比平台旧。私有能力只通过命名符号访问，不从反汇编推算地址或偏移。
