# Prepared native services across GC

The common native member provider prepares all tables, reflective mappings, resolution declarations, schema decisions, field-copy schedules and replacement-map capacity in the actual Collected window. Preparing these again inside ART's final Update callback is unsafe: native allocation may fail after ART has crossed its rejectable phase.

`prepared_roots::Registrar::add(owner, managed, &slot)` registers each nonnull live managed reference with the owner's real strong root registry. The provider also registers unchanged ancestors, loaders, copied-method declaring Classes and fallback interface closure roots. Root registration is a Collected operation and may fail there. The registry must preserve object identity across GC; descriptor names and previously cached addresses cannot substitute for actual roots. A null parent/bootstrap loader remains an explicit null identity.

After registration, the prepared containers and their native storage locations are frozen. The owner keeps the same `source_commit::Plan` object and source service alive, updates the existing Plan vectors from actual roots without resizing, and seals its independent final schema proof. `Resolver::get(owner, slot) noexcept` reads only frozen, predecoded root slots under the original exclusive/disabled-GC window. It obtains no JNI access, allocates nothing, and cannot suspend.

`native_member_provider::Service::RefreshManagedRoots(plan, source, resolver)` checks every participant's root slots before changing any pointer, then refreshes method Class identities, reflection/resolution Class graphs, captured native schema facts, field ancestry schedules and replacement-map entries in place. The source service argument must be the exact prepared service; unrelated services are rejected. Replacement map node/bucket storage stays fixed. In-place heapsort rebuilds bucket grouping in O(N log N); root IDs belong to the unchanged entry order, so repeated refreshes do not lose their correspondence when nodes reorder.

The refreshed final path checks pre-captured native Class/parent/loader identities, Java flags, native table storage, field/method declaring roots and DEX indexes. It does not parse DEX again or prepare a new schema policy. Mandatory `GuardVerifier::Verify` requirements remain in force and must themselves be allocation-free in this final window. Reflective scans use inline uncached resolution state and native descriptor comparisons. Linux mapped-region checks use direct syscalls and fixed buffers rather than allocation-backed stdio or a new mapping vector.

Host regression executes the actual composed provider/source path after moving both Class pairs and untouched Object, with all C++ allocation attempts fatal. It also changes final field flags/native tables and confirms refusal before retirement or heap mutation. The real host libc++ consumer verifies replacement maps after two relocations with no storage growth. These checks prove the common adapter's allocation behavior in the fixture, not the internals of real ART callees. Production root registration/phase integration and an owner guarantee against newly created unsupported handles remain necessary. Hierarchy and final-field capabilities still require their independent actual runtime services.
