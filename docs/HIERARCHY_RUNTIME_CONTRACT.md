# Rooted hierarchy runtime contract

The shared allocator in `platform/common/rooted_hierarchy_allocator.*` is used by the Android 13 source allocation adapter. This is an extraction of the real source path, not permission to apply hierarchy edits through the modern owner. The native schema policy records `HierarchyGraph` for changed parents or direct interfaces; its absence of an independently installed proof still refuses before copying or dispatch updates. The modern owner's first schema batch does not yet establish that proof.

## Fixed source boundaries

The pinned [Android 11](https://android.googlesource.com/platform/art/+/refs/tags/android-11.0.0_r1/openjdkjvmti/ti_redefine.cc), [Android 13](https://android.googlesource.com/platform/art/+/refs/tags/android-13.0.0_r1/openjdkjvmti/ti_redefine.cc), [Android 12](https://android.googlesource.com/platform/art/+/refs/tags/android-12.0.0_r1/openjdkjvmti/ti_redefine.cc), [Android 14](https://android.googlesource.com/platform/art/+/refs/tags/android-14.0.0_r1/openjdkjvmti/ti_redefine.cc), [Android 15](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/openjdkjvmti/ti_redefine.cc), [Android 16](https://android.googlesource.com/platform/art/+/refs/tags/android-16.0.0_r1/openjdkjvmti/ti_redefine.cc), and [Android 17](https://android.googlesource.com/platform/art/+/refs/tags/android-17.0.0_r1/openjdkjvmti/ti_redefine.cc) declare the same three-handle/index allocation entry: `ClassRedefinition::AllocateNewClassObject(old_class, super_class, cache, uint16_t)`. It delegates class setup and linking to ART, which rebuilds instance layout and virtual/interface tables for the supplied parent and incoming DEX. Common named declarations are in `platform/abi/arm64/android-common/hierarchy_allocation.h`; names alone do not establish safe roots, source ownership or runtime readiness. All seven pinned-source allocator signatures were inspected; their callable declarations agree. This does not prove the private Thread/Handle/Class/DexCache layouts or actual hook execution on those runtimes.

The common allocator selects parents using the original rooted loader, allocates explicit or affected implicit parents before children using an explicit dependency work stack, reuses exact rooted old-Class identities, and refuses cycles/ambiguous islands. A 1024-class host chain proves that depth does not consume recursive native frames; any failed source allocation poisons the current allocation batch until cleanup. It retains an early linked-Class result slot across the source `EnsureInstanceFieldIds` boundary, including the later OOM/null return. Failed transactions retire only independently captured unpublished replacement Classes while their source DEX owners are still alive. Return Class, loader, parent and DexCache identities are checked before installing the returned replacement identity. Root contents are freshly decoded after resolution and allocation; no borrowed managed pointer survives those operations.

## Required modern-owner integration

1. Stage public Class/loader/superclass/direct-interface identities and the complete affected descendant closure using strong roots. Resolve each requested parent/interface under that original loader, with independent access, initialized-parent, interface-kind, Object-root and acyclic-graph checks. Recheck the closure at both actual source windows. An IfTable closure alone cannot prove direct-interface input or loader resolution.
2. Bind the actual named source allocator and source subtree boundary under the same transaction gate. Independently calibrate GC-updated handle slots through named `HandleScopeVisitRoots`, including nesting, moving GC, chain restoration and original-thread lifetime. Fixed Thread declarations must come from source; do not search or guess field offsets. The Android 13 adapter has this source-root implementation; a modern adapter must prove its own fixed candidate before use.
3. Capture linked replacements before ID allocation can fail; retain original source Holder/old-new-Class/island/cache ownership and retire only this operation's temporary Classes on failure. Global callbacks or a plain installed boolean cannot attest a particular Plan.
4. Scope verification resolution and type-cache rewrites to the unpublished incoming DexCaches. Use the independently calibrated paired or dual-array cache model, preserve type indexes, refresh both allocated representations, invalidate native field/method caches and issue the actual DexCache write barrier. Published unrelated caches must remain unchanged.
5. When ancestry or implemented interfaces narrow, prove actual receiver checks across affected JNI, reflection, method/field handles, interpreter and compiled dispatch paths. Deoptimize affected compiled state under the original source commit and reject stale receiver identities. Existing source Android 13 receiver guards are not a generic proof for every runtime.
6. Seal the exact actual Class/instance graph and native parent/interface/field/method identities. Only then may `HierarchyGraph` verification authorize the prepared field-copy schedule to clear removed ancestor slots and retain exact typed paired ancestry. The new parent fields keep their allocation values; migrated objects do not rerun constructors or class initializers.

## Class modifier semantics

A legal combined final-to-abstract transition requires the same existing-instance proof as adding abstract alone. Abstract-to-final requires the full loaded-subclass proof. Final plus abstract is invalid, and Class/interface/annotation/enum role conversion remains refused. Existing constructor/class-initializer declaration stability is distinct from the source Class-object lock proof: the early CheckClass adapter must observe the real fixed `lock_acquired` field in the matched source prefix and preserve original CheckRedefinable semantics. Neither constructor presence nor a successful policy plan proves that source lock.
