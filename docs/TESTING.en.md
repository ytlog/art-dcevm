# Testing and diagnostics

English | [中文](TESTING.md)

This page covers builds, test execution and diagnostic checks. See [COMPATIBILITY.en.md](COMPATIBILITY.en.md) for existing public conclusions and [LIMITATIONS.en.md](LIMITATIONS.en.md) for rejection rules. Post-test diagnostics establish coverage; integrators must not turn them into pre-submission switches.

## Preparation and host checks

Source builds require JDK 17 or later, Android SDK 37, NDK 27.2.12479018, CMake 4.3.4 and `sdk.dir` in local `local.properties`. Build the sample app, library Debug and library Release separately to check test isolation:

```sh
mkdir -p build/evidence/documentation-check
./gradlew :app:assembleDebug :artdcevm:assembleDebug :artdcevm:assembleRelease
python3 tools/check-interface-abort-isolation.py
python3 tools/check-doc-links.py
for test in tools/test-*.py; do
  python3 "$test" > "build/evidence/documentation-check/$(basename "$test" .py).log" 2>&1 || exit 1
done
```

Host substitutes execute no ART objects, real hooks or collector and cannot replace device ABI checks.

`python3 tools/test-runtime-thread-host.py` compiles the production thread service and transaction context with fake named services, covering all seven Thread declarations, JNI/tid/flag rejection, missing Mark, marking changes after the Native probe, nested context restoration and CC/CMC call boundaries. It also covers compile-time `VerifiedThread` constraints, `LayoutFor`, positive/negative assertions for shared JNI prefixes, and preservation of unavailable mapping reasons. It does not simulate collector algorithms.

`python3 tools/test-structural-install-host.py` compiles shared production modules with fake public JNI/JVMTI tables and hook services. It checks installation order, idempotence, no JNI override attempt after inline-hook failure, base-capability fallback after JNI-table failure, and independent Thread preparation/diagnostic preservation when mapping names are missing. It executes no ART objects, collector or real hooks and does not replace device ABI validation.

`--scenario-group retransform` isolates 11 enhanced scenarios, also included in `tool` and full suites, on arm64 API 30–37 including 12L. An independent agent calls RetransformClasses through the public JVMTI table and supplies DEX only in ClassFileLoadHook. Verify field/method addition, retirement and restoration, compatible old-instance values, permanently retired cached references, GC, identical output, no replacement output, unchanged members of mixed batches, two-target commit, callback-nested retransform, exact callback/replacement counts and the next transaction after failure. Invalid second DEX must fall back with 60. A valid two-target batch must hit the mapping-plan fault exactly once, return 110, preserve both definitions and behavior after GC, then complete retirement in the next transaction. Structural success requires 0, empty lastRejection and observed new members; native rejection or the installation capability is insufficient.

`test-structural-install-host.py` runs 60 cases over the three legacy APIs' real declared strides, public-table matching, missing materializer, hook order/rollback, nested success/exception restoration, unchanged batches and mixed shared/equal buffers. Inaccessible guard pages prove unchanged lazy input is not read, a transformer can replace bytes without reading the current map, and required named materialization runs once. Also verify the three-attempt bound, identical complete vector, no repeated transformer/materializer and recovery of subsequent requests. `check-interface-abi-preparation.py` cross-compiles both layouts; `check-structural-symbols.py` reports both routing entries and the legacy-only materializer separately. Host fakes, arm64 compilation and real names are not old-device execution: API 30–32 currently lack corresponding device evidence; available API 33/36 devices verify the common route.

The app-owned test engine uses `-O2` while retaining Debug symbols, assertions and fault injection; standalone AAR build configurations are unaffected. `check-interface-abort-isolation.py` verifies these compiler settings. Completed scenarios retain UTF-8 JSON and release their original object trees so later ART whole-heap reference walks do not repeatedly scan report objects. Reports keep every scenario and check, with atomic `fsync`/rename publication.

The device runner records `totalSeconds` and per-command `commandSeconds` in `run.json`. New APKs also report scenario/JVMTI time, checkpoint time and the five slowest scenarios. Scenario time includes its checkpoints and JVMTI time; checkpoint totals stop before the current publication, so these measurements must not be added together. Use the relevant `--scenario-group` during iteration and run the applicable complete matrix before committing. Timing does not change return codes, assertions, scenario counts or the 30,000-call warm-up coverage.

`tools/compare-jbr-interface-removal.py` compiles the shared Java fixtures to ClassFile and runs them on fixed JBR `21.0.11+10-b1163.116`, using source revision `cf1f197170a0f04c6559feb873e362583be021d1`. A mismatched runtime is rejected as evidence for that reference:

```sh
python3 tools/compare-jbr-interface-removal.py --java-home JBR_REFERENCE_HOME
python3 tools/compare-jbr-field-retype.py --java-home JBR_REFERENCE_HOME

python3 tools/compare-jbr-invoke-kind.py --java-home JBR_REFERENCE_HOME
python3 tools/compare-jbr-interface-symbols.py --java-home JBR_REFERENCE_HOME
```

`compare-jbr-proxy-parents.py` shares the Proxy parent fixtures with device group `proxy-interface`: shared-parent retention and removal, retained calls and reference cleanup, restoration, simultaneously added parents also redefined by the batch, cached Proxy classes and repeated GC.

`tools/compare-jbr-field-retype.py` uses the same fixed runtime and shared field-retyping fixtures to check ordinary values, direct and indirect interfaces, dynamic proxies, inherited fields, restoration, repeated updates and GC.

`compare-jbr-interface-matrix.py` and device group `interface-selection` cover 22 receiver shapes: own/inherited private, package-private and protected declarations, distinct packages, split defining loaders and more specific public overrides. Separate lanes add abstract, default or parent-interface methods, switch abstract/default, and check old/later-loaded sites, interface reflection and cached MethodHandles, class calls, 30,000 hot calls, GC, later class loading, two rounds and planned aborts. Parent removal now also requires exact NSME at old and later-loaded symbolic child calls, including after GC. The device-report validator independently pins transport, access-flag and loader expectations.

`compare-jbr-interface-symbols.py` and device group `interface-symbols` distinguish the child symbolic owner from the unchanged parent declaration. They cover parent removal (NSME), added private/static hiding (IAE/ICCE), overriding receivers, null precedence, old and later-loaded calls, cached reflection/MethodHandle/JNI references to the parent, receivers losing the parent (reflection IllegalArgumentException, interface-handle ICCE, class-handle AME and parent-type cast CCE), preserved class calls, two restoration rounds, GC and atomic batch failure. JBR runs interpreted and scoped JIT modes with CheckJNI; ART injects failure after mapping planning and requires the peer to remain unchanged. Both oracle and device require fresh `findVirtual` to throw `IllegalAccessException` for the matching complete signature and `NoSuchMethodException` for a wrong return type. They also check new parent/override handles, static reflection/`findStatic`/unreflect, equal-name parameter and return Classes from two loaders, original access flags, cached handles and two rounds of failed restoration. The lookup caller warms up 30,000 times and repeats lookup 128 times per state; JBR JIT logs must prove that caller compiled. Host tests compile the production JNI guard and cover missing capability/symbols, unreadable locals, equal-name parameter/return Classes from distinct loaders, lazy-install failure/retry and failed removal of the Native probe Hook and preparation reentry.

Fixed JBR can fail a `javaCalls.cpp` parameter-count guarantee on JNI interface calls after adding an abstract member; cached reflection slots in indirectly rebuilt classes can also alias another method. Use `--probe-jni-failures` to reproduce added-abstract and default-to-abstract failures in isolated processes; the latter first proves successful JNI dispatch before redefinition. These crashes are recorded separately and do not count as passing JNI parity. Class-call oracles use original bytecode and symbolic MethodHandle lookup; these results do not claim that those JBR defects are fixed. The device matrix separately requires safe, correct JNI calls for new members and preserved class reflection calls.

`JBR_REFERENCE_HOME` path placeholder. Raw output and fixture, harness and runtime hashes stay under ignored `build/evidence/`. These comparisons cover specific interface-narrowing and reference-field rules, not complete JBR parity. ART device tests must check matching values, errors, field clearing and behavior after failure.

`compare-jbr-member-descriptors.py --java-home <fixed-jbr>` and device group `member-descriptors` share assertions for interface method synthetic/bridge/varargs/strict flags and interface/class field synthetic flags. Six variants run two apply/restore cycles, checking fresh and cached reflection, old and late-loaded calls, MethodHandle targets, old/new instances, reference values and GC. JBR checks exact InternalError for malformed-peer batches; ART injects failure after mapping-plan preparation in both directions and requires 110 with one fault hit and both definitions preserved. The 48 device scenarios are also part of `full`.

`compare-jbr-invoke-kind.py` and device group `invoke-kind` compare old static, virtual, super, inherited and range calls after static/instance changes in both directions, plus old static calls after interface static-to-default changes, including hot recompilation, caller/target active frames, GC, implicit rebuilds, restoration and failed transactions. Device group `method-private` also covers IAE for old external virtual/super/range calls, interface default-to-private IAE/NSME, overrides, legal new self calls, null receivers, hot calls, implicit rebuilds, deletion/re-addition and restoration. The JBR oracle runs default, interpreted and scoped compiled self calls. `method-private` also includes eight active batch-caller cases: two reverse-order rounds submit the target and caller base together, checking public-to-private changes, restoration, planning failures, old-frame IAE/old bodies, GC and retained fields. Missing-selector rejection for active target self frames remains separate. `method-private-self` isolates class/interface copied-default frames, ignored overrides, range, authorized null NPE, GC, two restore cycles and observed single-step callbacks. With either selector installed, the second round first updates the body to verify retained earlier DEX and rejection 71 for the other kind without a selector. API 33 without selectors skips that preliminary default-body update due to ART's obsolete-copy check and continues to verify private-transition rejection 71. `--private-self-mode interface-only|class-only|disabled` masks selectors before Debug initialization; reports must agree with the mask and per-kind expectations. Masking does not replace API 34/37 device validation. With both selectors masked, API 36's second hot copied-default cycle returns 71 but ART aborts while disabling single-step on duplicate JIT zombie code; reproduced in normal and CheckJNI modes, including fresh self-only processes. This stress combination remains blocked and is not a passing support claim. Keep single-step and frame protection intact when reproducing it. Device group `tool` isolates appended-subclass verification and a later redefinition of an added class, guarding the replacement class graph. `test-invoke-kind-host.py` checks both named-service ABI families, missing services, installation rollback and compilation flags; host fakes do not replace ART device validation. An isolated invoke-kind process retains its own live class-to-interface rejection witness and checks its identityHashCode, without depending on objects created earlier by the full suite.

## Device regression

Replace the `DEVICE_SELECTOR` placeholder and use an anonymous `--device-id`. The runner installs the requested APK, stops the previous sample process, removes its report and starts from initial definitions. It verifies the installed APK SHA-256 and complete scenario order, operating on the sample package `dev.artdcevm.lab`.

```sh
python3 tools/run-device-tests.py --serial DEVICE_SELECTOR --device-id android-device-1 \
  --apk app/build/outputs/apk/debug/app-debug.apk \
  --scenario-group full --checkjni-mode normal
python3 tools/run-device-tests.py --serial DEVICE_SELECTOR --device-id android-device-1 \
  --apk app/build/outputs/apk/debug/app-debug.apk \
  --scenario-group full --checkjni-mode checkjni
```

`ordinary` retains ordinary classes adding interfaces, skipping only interface targets; use it when interfaces remain inactive. `interface-abstract` isolates abstract additions; `thread-subclass` covers application `Thread` subclasses. `interface-removal` covers removal, repeated rebuilds, late descendants of abstract ancestors, JBR reference-field cleanup and restoration. `proxy-interface` covers Proxy implementations and grouped updates; `interface-drop-parent` covers an interface dropping a parent. `static-narrow` checks JBR static copying and `field-retype` checks field retyping. These groups do not replace full regression. `--timeout` controls instrumentation timeout; `--evidence-root` must stay under ignored `build/evidence/`. Require every expected scenario, error code, old definition and subsequent operation, not just the instrumentation process exit code.

`--scenario-group interface-shadow` checks JBR interface/class selection in 19 scenarios: static/private defaults, protected/package/cross-package IAE, reflection/MethodHandle/JNI/bytecode, 30,000 hot calls, late children and public overrides, AME for a private superclass declaration, restore/re-add, abstract/default transitions, defaults from added parents and mapping-plan rollback. `interface-abstract` additionally checks private AME and package/protected IAE through JNI, MethodHandle, bytecode and GC. `compare-jbr-interface-selection.py --java-home "$ART_DCEVM_JBR_HOME"` runs fixed JBR 21.0.11+10-b1163.116 with the same fixtures and classfile access recipes. `test-linking-dex-host.py` independently checks private DEX declarations, immutable interface-list masks, SHA-1, Adler32 and map entries. New selection device coverage is currently API 33/36 in normal and CheckJNI modes.

## Recovery and fault isolation

Full instrumentation checks old behavior, subsequent superclass/interface transactions and GC after failures in the same process:

```sh
adb -s DEVICE_SELECTOR shell am instrument -w -r -e checkjni false \
  dev.artdcevm.lab/com.github.ytlog.artdcevm.testing.InterfaceAbortInstrumentation \
  > build/evidence/documentation-check/abort-normal.log 2>&1
adb -s DEVICE_SELECTOR shell am instrument -w -r -e checkjni true \
  dev.artdcevm.lab/com.github.ytlog.artdcevm.testing.InterfaceAbortInstrumentation \
  > build/evidence/documentation-check/abort-checkjni.log 2>&1
```

Add `-e scenario ordinary` for ordinary classes only. `-e runtimeProbe 13`, `14` and `15` use separate processes for Thread, HandleScope and holder rejection. Fault numbers are defined by [fault_injection.cc](../app/src/debug/cpp/testing/fault_injection.cc) and [InterfaceAbortInstrumentation.java](../app/src/debug/java/com/github/ytlog/artdcevm/testing/InterfaceAbortInstrumentation.java); removing traversal callbacks also removed 6, 7, 9 and 10.

Recovery checks also cover admission/lookup/array-transfer hook-boundary exceptions, Native scope-construction failure and nested context restoration. The pending root must cover replacements not yet stored in private arrays. Injected allocation failure does not establish recovery from real memory exhaustion.

`InterfaceAbortInstrumentation` exercises real DEX verification failures (an invalid return instruction and calling `String.length()` with an integer receiver, both returning 62), failure after linking, after full allocation, during instance allocation, and from the actual mapping probe in one process. Each failure is followed by superclass and interface redefinition, behavior checks and GC. The incompatible invocation is followed by explicit GC before further transactions. A transforming ClassFileLoadHook also tests a real retry after a late implementation loads. Only the app test module explicitly enables fault injection and test JNI exports through its Debug CMake arguments. It builds a test copy from the same engine source directory. Library-owned Debug and Release builds default to OFF and reject an enabled option in a standalone library build. The test APK selects the app copy. `tools/check-interface-abort-isolation.py` uses `llvm-nm` to check both AARs and their Build-ID-matched unstripped libraries for absent injection symbols, and confirms the APK Build ID belongs to the app test engine.

## Thread and GC pressure

Select and verify normal/CheckJNI mode before installation. See [compatibility](COMPATIBILITY.en.md#covered-scenarios) for late loading, nested interfaces and instance/mapping failures. `interface-stress` must capture exactly 207 types from 200 implementations, four diamond subinterfaces and two affected superclasses; `interface-stress-add` also covers member additions.

Before the first interface transaction, `InterfaceAbortInstrumentation` injects an ordinary-class Thread probe failure and verifies code 67, the `memberMapping` reason, zero shared reference reads and preservation of the old definition. It then alternates at least 32 ordinary-class structural redefinitions while another thread retains about 197,000 live objects, continuously allocates and requests GC. If marking reads remain zero, retries are bounded by 512 transactions or 120 seconds. Checks cover field/method additions and removals, primitive values/reference identity in old instances, zero-initialized new fields and subsequent GC. Reports include total GC cycles, allocations, shared reference reads and reads during CC marking. CMC may report zero for the last metric; GC pressure alone does not prove that every transaction overlaps CC marking. `ordinaryGcCycles` includes GC initiated by ART structural transactions and cannot alone establish independent pressure. The worker calls public `Runtime.getRuntime().gc()`, waits for one return and checks that the GC count advanced before starting transactions. `ordinaryPressureGcRequests`/`ordinaryPressureGcReturns` count worker calls/returns; `ordinaryPressureReadyGcCycles` records that preparation interval. A returned request is neither a distinct-collection count nor marking-overlap evidence.

Fixed Android 17 [System.gc](https://android.googlesource.com/platform/libcore/+/refs/tags/android-17.0.0_r1/ojluni/src/main/java/java/lang/System.java) coalesces requests for targetSdk ≤ 34: a standalone call can only set a flag awaiting finalization. [Runtime.gc](https://android.googlesource.com/platform/libcore/+/refs/tags/android-17.0.0_r1/ojluni/src/main/java/java/lang/Runtime.java) enters the public native request directly. [Redefiner::Run](https://android.googlesource.com/platform/art/+/refs/tags/android-17.0.0_r1/openjdkjvmti/ti_redefine.cc) uses ScopedSuspendAllocations to collect before instance collection and the main mapping preparation, and waits for/disables concurrent moving GC before final updates. The old fixture’s GC total and zero marking reads therefore do not establish a Thread-offset error. Run `python3 tools/analyze-runtime-gc-log.py --logcat <raw-log> --device-id <anonymous-id>` offline to check CC/CMC completion process/thread provenance and snapshot order without reporting raw process/thread IDs. Completion logs do not establish marking intervals or forwarding. The corrected pressure fixture still needs API 37 device execution; earlier zero-overlap observations stand.

## Named-service audit

```sh
python3 tools/check-structural-symbols.py --report build/evidence/documentation-check/symbols.json
```

The checker audits implementation references, named ELF tables and catalog/implementation hashes, without disassembly or address/offset derivation. Admission spellings are alternatives; the catalog total is not a count of names simultaneously required on one device.

Private ART capabilities are accessed only through named ELF symbols. The hook library resolves them at runtime within the table scope declared in the catalog. `.gnu_debugdata` is also a named symbol table; no disassembly or address derivation is involved.

- [structural_redefine_symbols.h](../artdcevm/src/main/cpp/platform/symbols/structural_redefine_symbols.h): 24 currently used names provided by every runtime. Of these, 19 require `.dynsym`; the standard JVMTI wrapper, JNI visitor, two MethodHandle entries and old-frame identity entry allow any named table.
- [constructor_history_symbols.h](../artdcevm/src/main/cpp/platform/symbols/constructor_history_symbols.h): both native constructor-discovery spellings, caller/access services and standard JNI weak identity comparison. The named predicate is probed with same/different objects; a missing predicate uses the public JNI table. ART maintains the weak references.
- [member_retirement_symbols.h](../artdcevm/src/main/cpp/platform/symbols/member_retirement_symbols.h): variable spellings used by retirement guards: `Method_invoke` and `Constructor_newInstance0` without a suffix or with a fixed `.__uniq` suffix, old and new `EncodeFieldId` signatures, and optional `MethodHandleInvokeExactWithFrame` from Android 13 onward.
- [verification_redirect_symbols.h](../artdcevm/src/main/cpp/platform/symbols/verification_redirect_symbols.h): old and new `FindClass` signatures used by verification redirection.

- [runtime_thread_symbols.h](../artdcevm/src/main/cpp/platform/symbols/runtime_thread_symbols.h): shared `CurrentFromGdb`, `ReadBarrier::Mark` and optional `gUseReadBarrier` for ordinary classes and interfaces.
- [interface_redefinition_symbols.h](../artdcevm/src/main/cpp/platform/symbols/interface_redefinition_symbols.h): the active interface catalog covers normal/structural `CanRedefineClass`/`GetClassRedefinitionError` alternatives, `FinishNewClassAllocations`, `Run`, `HandleScopeVisitRoots`, `EnsureInitialized`, `NewLocalRef`/`DeleteLocalRef`, `CreateNewDexCache`, two `DoLookupResolvedType` overloads, two `LookupClass` signatures, `SetDexCache`, `JavaVMExt::DecodeGlobal`, `LinkClass` and `SetStatusInternal`, plus optional named alternatives for `ThrowIllegalAccessErrorForImplementingMethod`. It reuses `GetMirrorClass`, `AllocateNewClassObject` and `FindInstanceField` from the structural catalog.
- [interface_abi_preparation_symbols.h](../artdcevm/src/main/cpp/platform/symbols/interface_abi_preparation_symbols.h): four historical array-allocation names for offline checks, including two AllocatorType overloads. Runtime code neither resolves nor calls them; exact signed/unsigned root traversal names live in the active interface catalog.

A symbol's presence proves only that it can be located. Runtime probes check the fixed declarations; device regression checks hook coverage.

## Diagnostic report reference

`DcevmRuntime.capabilities()` reads diagnostics without running probes or deciding whether a request may be submitted. Call standard `RedefineClasses` directly: `0` means success; otherwise read the code and `lastRejection`. The following table preserves the existing JSON keys and value descriptions for troubleshooting and post-test coverage checks. `interfaceAddition` means adding an interface to an ordinary class; `interfaceRedefinition` describes interface runtime probes. Do not build an integrator admission switch from these booleans or strings.

| Key | Meaning |
| --- | --- |
| `installed`, `standardRedefineRouted` | Base entries are installed, and standard `RedefineClasses` is routed to the structural transaction |
| `memberAddition`, `memberModifierChange`, `classModifierChange` | Member additions and member/class modifier changes; true after installation |
| `methodDeletion`, `methodSignatureChange`, `interfaceAddition` | Method-retirement hooks are installed |
| `fieldDeletion`, `fieldTypeChange`, `memberDeletion`, `memberTypeChange` | Field guards are also available |
| `superclassWidening` | Method-retirement hooks and verification redirection are both installed |
| `interfaceRemoval` | Method retirement, pre-publication dispatch protection, instance-reference checks and ClassPrepare snapshot monitoring are available; an ordinary class may remove an interface |
| `interfaceDispatchSealing` | `available: ...` or `unavailable: reason`; records the executed pre-publication linking boundary and canonical source, and also requires named allocation services and the class-loader allocator read |
| `privateSelfSelectionClass`, `privateSelfSelectionInterface` | Named self-call selection service and dependencies installed for that target kind; transactions also need layout probes |
| `privateSelfSelection` | Conjunction of the two services, preserving the existing diagnostic |
| `privateSelfSelectionClassReason`, `privateSelfSelectionInterfaceReason` | Empty when available, otherwise the unavailable reason |
| `hierarchyChange`, `fullDcevmComplete` | Always false: superclass narrowing is unsupported and full DCEVM is not complete |
| `interfaceRedefinition` | Boolean: true only after installation and all Class/Thread/HandleScope/holder probes pass. False before probing, when versions/services are unavailable, or after process-wide probe disablement. A target-specific rejection does not clear it |
| `interfaceRuntime` | `unavailable`, `unverified: interface runtime declarations`, `verified: androidNN Class/Thread/HandleScope/holder probes`, or `disabled: reason`. API 30–37 are admitted; a verified source-aligned release (API 30–32, 37) adds `; declarations not yet device-validated`; other versions are disabled with a reason |
| `interfaceSnapshotTypes` | Type count in the calling transaction thread's latest interface snapshot: targets, subinterfaces, implementations and their subclasses |
| `interfaceSnapshotNanos`, `interfaceAllocationNanos` | That thread's latest snapshot (including GetLoadedClasses) and interface allocation durations in monotonic nanoseconds; diagnostic only, potentially zero without an interface transaction |
| `memberMapping` | Installation-unavailability reason or latest probe result (including Native Thread failures): `unavailable`, `unverified`, `verified: androidNN class layout`, or `rejected: reason` |
| `jniRetirementGuards` | Count of actual JNI/reflection guard rejections of retired targets |
| `subclassLoadRetries` | Count of retries caused by a subclass of a target loading during a transaction; see [class loading during transactions](STRUCTURAL_REDEFINE_ENGINE.en.md#class-loading-during-transactions) |
| `diagnostic`, `lastRejection` | Installation diagnostics; the classes and reason of the latest standard-entry transaction failure, empty on success. Rejections by the policy, the snapshots and the pre-commit checks state their own reason. When one of ART's own checks rejects the batch (a boot interface, for example, is rejected with 79 at its entry), the standard entry names the rejected interface or unmodifiable class, or otherwise lists the batch's classes and the error name; ART's own message appears only in logcat after `FAILURE TO REDEFINE` |

## New-release validation order

1. Run `--scenario-group ordinary` and abort instrumentation’s `-e scenario ordinary` in both JNI modes. After retirement scenarios, confirm completed `memberMapping` probes so fallback is not counted as a pass. On Android 14 and later, confirm actual CC and CMC configurations separately.
2. Review one release at a time: fixed Class, Thread, HandleScope, holder, ClassRedefinition flags, IfTable/PointerArray and named prototypes. Begin with declarations/offline checks; compilation or a cloud device catalog entry is not execution evidence.
3. A release may be admitted as `kSourceAligned` once its fixed declarations are reviewed and every stored device library of the release provides the required named services (`check-interface-abi-preparation.py`). Promote it to `kDeviceVerified` in a separate commit only after the complete interface suite, abort recovery and android-compose-hotreload’s `interface abstract batch` pass on real devices.

## Retained JNI IDs after receiver interface loss

Build the ordinary debug APK for `--id-mode index`. For `--id-mode mixed`, build a separate APK with `./gradlew -PjniPointerProbe=true :app:assembleDebug` and freeze both APKs before running. The opt-in Debug [wrap script](https://developer.android.com/ndk/guides/wrap-script) starts swapable IDs with automatic promotion disabled. The debug-only probe loads the public JVMTI client, caches IDs before attachment when requested, suspends other Java threads using public JVMTI, and calls the fixed named `Runtime::SetJniIdType` service. This reproduces ART's pointer-to-index test transition without changing offsets or flags; it is excluded from both library AARs.

```sh
python3 tools/run-jni-receiver-tests.py --serial DEVICE_SELECTOR --device-id android-device-1 \
  --apk <frozen-pointer-debug.apk> --id-mode mixed
python3 tools/run-jni-receiver-tests.py --serial DEVICE_SELECTOR --device-id android-device-1 \
  --apk <frozen-debug.apk> --id-mode index
```

Each invocation runs 96 isolated processes: before/after attachment, default-only/own implementation, interface/class lookup, virtual/nonvirtual, plain/V/A and normal/CheckJNI. Mixed mode must observe tag 0 before promotion and tag 1 afterwards: 48 completed call cells, 36 original CheckJNI diagnostic cells and 12 separate rejection-79 cells. Index mode requires tag 1 in both cache timings: 60 call cells and 36 diagnostic cells. A rejection cell verifies atomic failure, retained calls/identity/fields, GC and successful later peer transactions; it never counts as a successful receiver-loss call. Call cells cover two rollback/application/restoration rounds, reverse batch order and GC. CheckJNI cells persist the successful transaction before the deliberately invalid call, then require the original receiver or nonvirtual class-argument diagnostic and SIGABRT. An obsolete-DexCache assertion, another crash, missing observations, wrong ID tag or self-consistent but wrong expected/actual values fail validation.

Record the device epoch before each launch and bound logcat by both PID and start time; PID reuse must not import another process's old diagnostic. Raw reports and logs stay under ignored `build/evidence/jni-receiver/`. `--replay <evidence-directory>` with the same `--apk` and `--id-mode` independently revalidates all saved cells and writes a separate `audit.json`, preserving the original run. Run both devices, their ordinary/CheckJNI complete suites and independent recovery tests before accepting a production change. The fixed JBR oracle covers plain/V/A/nonvirtual JNI boundaries; it does not establish ART pointer/index behavior.

`ReceiverLossAdapters` supplies 43 prelinked graphs to ART and the fixed JBR harness. `method_handle_adapter_expectations.py` pins independent results and callback traces for both report validators. Checks include binding after composition, ignored/replaced receivers, guard branch selection, handlers inside/outside binding, throwing filters, collect/fold, permutation, spread/collect, invokers, explicit casts and varargs. `test-captured-method-handle-host.py` exercises 34 rooted continuation, upcall failure, metadata retry, entry identity and pending-exception cases. The entry suite also verifies missing frame-return services/coverage, failed continuation preparation, early-return failure and another agent's forced return. `python3 tools/run-jni-frame-tests.py --serial DEVICE_SELECTOR --device-id android-device-1 --apk <frozen.apk> --id-mode index` adds native-caller and old-Java-body parking to every JNI receiver-matrix cell, for 192 isolated processes.
