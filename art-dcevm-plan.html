ANDROID RUNTIME / DYNAMIC CODE EVOLUTION · 2026-10-04 修订

无 root，在应用内对齐 DCEVM

采用“标准 JVMTI + ART 增量结构扩展 + 构建期兼容层”三条路径。目标是在 Android 8.0–17 上实现保留进程和业务状态的开发期热更新；原生结构能力按运行时探测启用，跨版本能力由预先接入的编译改写提供。

完整 DCEVM 语义不能作为所有版本、所有类和所有调用方式的统一承诺：成员的物理删除、已有对象的真实继承关系变化，以及未改写的反射/JNI 透明访问，仍有明确边界。

先固定实施边界

主交付

自有调试应用

APK 从启动时就可调试，在构建期接入插件与 SDK，Agent 随 APK 打包。在应用内完成加载、探测和更新；无 root、无系统签名、无系统分区修改。

补丁作用域

明确可更新的业务代码

声明热更新类与调用方范围。Framework、核心类及第三方未纳管代码不纳入统一结构更新承诺。多进程各自建立会话，不承诺跨进程原子更新。

兼容交付

正式版只保留受控适配

debuggable=false 不能走公开的完整 JVMTI attach 路径；profileable 也不等价。可保留构建期分派能力，但不能宣称正式版具有完整 DCEVM 能力。

普通权限不禁止应用修改自身可写内存或在条件允许时执行自身 Native Hook；约束在加载入口、系统策略和正确性。ADB 可用于开发传输和测试，但 shell 权限不计入运行时必需能力。ART TI 依据

Android 8.0 到 17：版本与能力矩阵

截至 2026-10-04，最新稳定大版本为 Android 17 / API 37。下表按各版 android-版本_r1 源码标签核对；不是 OEM 或所有 QPR/APEX 构建的实测认证。官方发布依据

系统 / API应用内接入ART/JVMTI 差异本方案落点
8.0 / 26已有 ART TI；无公开 Debug.attachJvmtiAgent。标准重定义拒绝成员增删。源码存在隐藏 VMDebug.attachAgent(String)。源码隔离的 O 版本自附加适配器；失败时已预置兼容层的类仍可走 C。若只用公开 API，本版预先选择 C。
8.1 / 27同 8.0，隐藏单参数入口需设备验证。仍为非结构化重定义；不能套用 API 28 的公开方法或参数签名。源码独立验证 8.1；attach 成功不代表具备结构能力。
9 / 28新增公开 Debug.attachJvmtiAgent，仅调试应用。支持标准方法体重定义；无本方案所需的结构扩展。开始非 SDK 接口限制。依据方法体用标准 JVMTI，结构变化用构建期兼容层。
10 / 29沿用公开 attach。发布标签仍无结构化入口；2019 年开发分支的提交不等于 Android 10 发布能力。源码同 9；原生代码定位还需考虑 APEX 模块布局。
11 / 30公开 attach。出现批量 com.android.art.class.structurally_redefine_classes：只增方法/字段，禁止删除及层级变化；需索引式 JNI ID 和完整调试条件。源码增加可探测的原生结构后端；静态/实例字段及虚方法分别验证。
12 / 31公开 attach。结构扩展约束延续 11；ART 可通过 Google Play 系统更新演进。源码 模块依据能力缓存加入 ART 构建标识，不只使用 SDK_INT。
12L / 32公开 attach。核对 android-12.1.0_r1，结构扩展契约与 12 相同。源码保留独立测试项，不遗漏 12L。
13 / 33公开 attach。仍为增量结构能力，不等于完整 DCEVM。源码三条路径按实测能力选择。
14 / 34公开 attach。完整 JVMTI 判断使用启动时可调试状态；结构扩展仍需索引式 JNI ID。target ≥ 34 的文件式动态代码加载要求文件只读。源码 规则从 APK 启动状态满足条件；正确创建只读补丁文件，不依赖事后翻转 debug 标志。
15 / 35公开 attach。批量结构入口保留；旧 UNSAFE…structurally_redefine_class_direct 已移除。支持 16 KB 页面设备。源码 规则只选择批量入口；Agent 和 Hook 库均验证 4 KB / 16 KB。
16 / 36公开 attach。标签中批量增量契约及类限制延续；未解锁物理删除、签名替换或层级变化。源码重跑 ART 构建探测、编译模式与 OEM 回归。
17 / 37公开 attach。批量增量契约仍在。运行于 17 且 target ≥ 37 时，反射修改 static final 抛异常，JNI 写入会使应用崩溃。源码 规则不采用反射/JNI 回填 static final；补测分代 GC、内存和旧版本回收。

11+ 是带条件的源码能力：必须同时满足扩展可枚举、类级检查通过、该 ART/OEM 构建用例通过。索引式 JNI ID 通常由可调试运行时启动流程配置；不能把 jmethodID/jfieldID 当裸指针，也不私自切换它的表示。

Android Studio Apply Changes 的产品范围与底层扩展不同：其文档仍将字段增删列为需重启。本方案的字段新增是自行实现并验证 ART 扩展，不用 IDE 支持范围代替运行时证据。官方说明

与 DCEVM 按语义逐项对齐

“逻辑支持”只对构建期纳管范围有效；“原生支持”由 ART 完成元数据、对象引用和执行状态的一致性处理。补丁结果中分开报告。

可承诺的结果：在声明的业务范围内，跨 Android 8–17 提供接近 DCEVM 的编辑体验；在通过验证的 11+ 运行时上增加真实成员演进能力。若要求“任意类、无改写、物理增删、层级变化、原生反射/JNI 全透明”同时成立，本约束下没有可保证的通用实现。

A / BASELINE

标准 JVMTI 后端

方法体变化，批量调用 RedefineClasses。安全点、obsolete 方法及 JIT/AOT 一致性由 ART 处理。

8.x 适配成功时可用，9+ 公开 attach；始终检查 capability 与类可修改性。

B / NATIVE ADDITIVE

结构化重定义后端

调用枚举得到的 com.android.art.class.structurally_redefine_classes，schema 只增不减。

11+ 候选；ART 负责分派表、实例迁移、JNI ID、GC 引用、反射和去优化。

C / PORTABLE

构建期演进后端

稳定类外壳 + 分派表 + 版本实现 + HotState；把结构变化转换为受控逻辑演进。

8–17 通用设计目标；不依赖 ART 私有布局，初始 APK 和调用方必须已纳管。

可选适配：PLT / Inline Hook → 自有 Native 边界、诊断和特定构建适配。每个 Hook 独立验证并匹配 ELF/ART 构建；不承担通用类演进协议。

构建时固定每个更新域的模型：需要在 8–17 上持续结构演进的业务类选 portable，结构变化一直走 C；需要真实反射/JNI 成员语义的类选 native，走 A/B，B 不可用时拒绝结构变化或重部署。不能等扩展失败后，才把已运行的原生对象无迁移地转成逻辑槽。A/B 的 VM 提交与 C 的分派发布不是自动原子事务；跨后端有强一致依赖时拒绝或等待业务静默窗口。

结构演进具体怎么做

B：使用 ART 的真实能力

  • 先查 IsModifiableClass，再查扩展 is_structurally_modifiable_class。原始类型、数组、接口、代理类及部分核心类有源码限制。
  • 每个 jvmtiClassDefinition 提供只含一个类定义的 Dex；批量提交依赖集合。不能将 JVM class 文件直接传给 ART。
  • 保留旧成员描述符与修饰符。删除变成逻辑停用；签名/类型变化变成新增与桥接。原生反射仍能看到保留的旧成员。
  • 已有字段值由 ART 保留/迁移；新增实例字段不能期待对旧对象重跑构造器，静态字段也不假设重跑 <clinit>。非默认初始化使用显式版本迁移协议。
  • Unsafe 缓存偏移、直接解释 JNI ID 的库、带指针式 JNI ID 标记的类/子类可能无法迁移；检出即拒绝，不能仅绕过检查。

C：用编译改写覆盖旧版本

  • 首次构建加入固定分派桥和 HotState 引用；后续实现使用唯一类名或版本加载器，外壳及真实继承关系固定。
  • 新方法映射为 MethodId → implementation，新字段映射为 FieldId → typed slot；ID 包含加载器身份，避免同名类冲突。
  • 删除使用墓碑；字段改类型分配新 ID，转换器决定迁移或拒绝。旧调用留桥或明确报链接错误，不偷偷套用新签名。
  • 优先对象自持 HotState，让 GC 处理对象环；全局“弱 key、强 value 且 value 反向引用 key”仍可能泄漏。
  • 纳管读写、直接/虚调用和受控反射访问；JNI、序列化、ORM、依赖注入及未改写库通过固定接口桥接，否则列为不支持边界。
编译器与语言语义不能省略

保存 Kotlin 编译器、D8/R8 配置与符号映射；热更新域避免抹掉稳定桥的优化。Kotlin inline 和常量变化必须更新受影响调用方。suspend 状态机、lambda 捕获、data class、默认参数、enum 变化应按最终 Dex 分类。

保持构造器父类初始化序列、final 发布语义、volatile、对象锁及异常行为。状态转换器不能在任意 ART 暂停窗口中运行阻塞业务逻辑；17 / target 37 不允许以反射/JNI 写 static final 补救。

类加载与身份

同名类放进新 ClassLoader 会形成不同类型，原对象、强转、instanceof 和 JNI 句柄不会自动迁移。C 只替换外壳背后的实现，B 的真实迁移交给 ART。新增独立类需规划加载器可见性、包访问与桥接，原 AppClassLoader 不会自动看见子加载器类。

PLT Hook 与 Inline Hook 能补到哪一层

机制能覆盖不能自动覆盖项目用途
PLT / GOT Hook
ByteHook		经过目标 ELF 导入重定位槽的 Native 外部调用；可处理后续加载库。同库直接调用、内联代码、直接系统调用及绕过槽的函数指针。Java 方法/字段和 JNI 函数表调用不普遍经过 PLT。自有 Native 依赖替换、加载时机观测与诊断，不作为类重定义主入口。
Native Inline Hook
ShadowHook		目标机器码入口或指令，覆盖部分不走 PLT 的直接调用；应用内在可用内存策略下可实施。内联副本、已执行的栈帧及 JIT 换址后的代码；自身不提供安全点、对象迁移、GC 或 JNI/反射一致性。自有 Native 函数替换；少量逐构建验证的 ART 点作为实验适配。
Java / ArtMethod 入口替换配合 ART 适配拦截部分 Java 调用。AOT/JIT 内联、去虚化和不同解释/编译入口可能绕过；改 entrypoint 不会增加字段、扩展对象或改变类层级。独立研究项，需另证去优化、重编译和入口生命周期，不替代 A/B/C。

ByteHook 当前声明 Android 4.1–17，支持 ARM 与 x86 ABI；ShadowHook 声明同一系统范围，但仅支持 armeabi-v7a / arm64-v8a。Hook 库的系统支持不等于 libart 私有函数或本项目语义已兼容。需验证 RELRO/页面权限、指令重定位、缓存同步、BTI/PAC/CFI 相关约束及 16 KB 页面，不能按 API 硬编码偏移。

“Hook 掉校验”补不齐 DCEVM：字段删除、层级变化影响对象大小、字段偏移、引用扫描、分派表、内联代码、栈帧和外部句柄。绕过错误返回没有实现这些协议。特定构建上可研究重实现 ART 内部逻辑，但工作量与维护性质已接近逐版本运行时补丁。

一次补丁的执行流程

  1. 生成与分类比较最终 Dex，计算调用/内联/类型依赖闭包，标记方法体、原生增量、逻辑演进或需重启。
  2. 核验与探测匹配 APK、epoch、加载器、ABI 与 ART 构建；查潜在能力，申请后读回；扩展及专用探针通过才启用。
  3. 准备与隔离校验 Dex、准备状态转换及版本实现；按只读规则创建文件。预加载/类初始化可能有副作用，不能称完全无副作用预检。
  4. 执行选定提交域A/B 使用批量 VM 调用；C 原子发布不可变分派快照。强状态迁移先关闭受控入口、排空旧任务，超时拒绝。
  5. 确认与恢复核对行为、字段值、版本与错误码。标准 RedefineClasses 的原子安装不包含业务迁移、I/O 或其他进程。
  6. 旧版本延迟回收A/B 遵从 ART obsolete 生命周期；C 追踪活动调用与延续对象。不可逆状态失败不能声称已自动回滚。

选择规则

先匹配构建清单中的更新域模型：native 的纯方法体变化选 A，合法追加且 B 探测通过选 B；portable 的纳管变化选 C。其余返回 RESTART_REQUIRED 或明确拒绝原因，不在失败后擅自改变对象表示。结果同时报告实际后端和语义等级。

原因码包括 AGENT_UNAVAILABLE、STRUCTURAL_EXTENSION_MISSING、CLASS_UNMODIFIABLE、POINTER_JNI_ID、CALLSITE_NOT_COVERED、HIERARCHY_CHANGE、STATE_MIGRATION_REQUIRED。

原子性与回退边界

C 的同步调用链固定 epoch；跨线程任务/协程需显式携带上下文，或在迁移前排空，ThreadLocal 不足以覆盖协程恢复。允许新旧并行时，状态格式需双方兼容。

B 成功增加的物理成员不能删除回退；可保留 schema 回退行为。有不可逆状态/I/O 时需前向修复或重启。业务状态迁移采用协作协议，不能把 SuspendThreadList 当完整 ART 提交协议。
